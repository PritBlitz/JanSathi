# CLAUDE.md — operating guide for AI sessions

JanSathi is a multilingual, voice-first navigator for Indian government schemes. **Read [docs/PROJECT_BRIEF.md](docs/PROJECT_BRIEF.md) first; it is the source of truth.** If the brief and the code disagree, ask the maintainer which is right. Don't guess.

## Non-negotiable principles

1. Never write copy that says "you are eligible", "you will get" or "guaranteed". Use "you may be eligible", "likely relevant" or "need more information".
2. Never show a scheme fact without a linked source record carrying `source_url`, `fetched_at` and `verified_at`.
3. No official source found → say "I couldn't find an official source for this". Never answer from model memory.
4. Out-of-date facts (source changed, or past the re-verification interval) carry a visible warning.
5. Every user-facing string goes through i18n (`t('key')` from `useI18n()` + `frontend/public/locales/*.json`). No hard-coded UI text.
6. Every interactive element works with voice/TTS and has an accessible label.
7. Collect the minimum personal data. The profile stays on the device where possible; the user can delete everything.
8. Never store Aadhaar or bank account numbers. Documents are "have / don't have" unless the user uploads for OCR; uploads are deleted after processing.

Also: **the rules engine decides eligibility; the LLM only explains.** Never let model output change a match result.

## Run and test

```bash
npm run setup        # once: install the frontend's dependencies (React, Vite)
npm run dev          # Vite dev server on http://localhost:5173 (proxies /api to the backend if running)
npm start            # build frontend/dist and serve it on http://localhost:8000
npm run start:backend   # API on http://localhost:8080 (OpenAPI at /v3/api-docs)
npm run test:backend # Java engine on the shared fixtures, API, assistant, retrieval evaluation
npm run build:jar    # PWA (API mode) + API in one jar
npm run check        # validate content, copy lint, locale parity, bundle freshness, unit tests
npm run build        # rebuild frontend/public/data/bundle.json and bundle.preview.json after editing content/
npm run smoke        # build, then headless Chrome walk-through; fails on console errors
                     # options: -- --lang hi --scheme light --shots DIR --url http://localhost:8080/
python ingest/recheck.py [slug] [--update slug] [--hash-file saved.html]
```

The root tooling has no dependencies; only `frontend/` does. CI runs axe (in the smoke test), Lighthouse, the size budget and the retrieval evaluation.

## Content rules (scheme data)

- Every fact comes from an official source you have actually read. Record the clause in `locator`, and fill `fetched_at` and `content_hash` (via `recheck.py`). Never set `verified_at` or `verified_by` by hand: only `tools/publish.mjs` sets them, after two independent approvals of the exact current content (AI reviewer agents or people, recorded in `content/reviews/`; see [docs/REVIEW.md](docs/REVIEW.md)). Never approve content you wrote in the same session.
- `confirmed` rules rest only on `gazette` or `guideline` sources; `portal`, `govt_statement` and `faq` give `guidance` at most.
- When a scheme changes (Cabinet decision, renamed scheme, revised criteria), update the file and say so in the content; don't keep stale rules.

## Working rules

- When adding a UI string, add the key to **all 10** locale files (English text as a placeholder, marked for review) so key sets stay identical.
- Follow [DESIGN.md](DESIGN.md) for visuals: tokens, hero, motion limits, performance budget.
- Keep every external provider (LLM, embeddings, translation, STT/TTS, OCR, notifications) behind an interface.
- Docs must say what exists now and mark everything else as planned.
- Commit only when asked.
